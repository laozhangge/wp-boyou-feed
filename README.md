# WP 博友动态

[![License: GPL v2](https://img.shields.io/badge/License-GPLv2-blue.svg)](LICENSE)
[![WordPress](https://img.shields.io/badge/WordPress-5.5%2B-21759b.svg)](https://wordpress.org/)
[![PHP](https://img.shields.io/badge/PHP-7.4%2B-777bb4.svg)](https://www.php.net/)

把 FreshRSS 里订阅的博友更新聚合到自己博客的一个页面，顺带对账：**这些博友最近一次来你博客留言是什么时候**。

> 插件不自己抓 feed，数据源是 FreshRSS（Google Reader API）。它做的是前台页面和一本账。

作者：[老张](https://laozhang.org)　｜　下载：[Releases](../../releases/latest)　｜　更新日志：[CHANGELOG.md](CHANGELOG.md)

---

## 它解决什么问题

博客写久了，订阅列表会到一两百个站。想知道的事其实就两件：

1. **他还在写吗** —— 他自己的站最近一次发文章是什么时候。
2. **他还来我这儿吗** —— 他最近一次在我博客留言是什么时候。

以前是开 FreshRSS 看未读、再回评论列表翻这是谁。这个插件把两件事放进同一张表，并且把该做的操作也放进后台了，不用再来回登 FreshRSS：

- 评论列表里，最近来留言但你没订阅的人，行尾有「添加订阅」，点一下就把他的 feed 订进 FreshRSS
- 对账表里每个站旁边有「删除订阅」，确认是死站、或者早就不来往的，当场删掉
- 「久未更新」「站点异常」两档筛选，专门用来找该删的站

## 前提：你得有自己的 FreshRSS

插件**不含**抓取逻辑，文章数据全部来自 FreshRSS。装之前先确认：

- FreshRSS 已部署，并且开了 API（设置 → 管理 → 认证 → 允许 API 访问）
- 知道 API 地址，形如 `https://rss.example.com/api/greader.php`
- 有一个能登 FreshRSS 的用户名和密码 —— **建议单独建一个只读账号**给插件用

没有 FreshRSS 的话，这个插件没有意义。

## 安装

1. 从 [Releases](../../releases/latest) 下载 `wp-boyou-feed-x.y.z.zip`
2. 后台「插件 → 安装插件 → 上传插件」启用
3. 左侧出现「博友动态」→「设置」，填 FreshRSS 的 API 地址、用户名、密码，保存
4. 点「立即同步」，看到「✅ 同步完成」和数据文件正常
5. 新建一个页面，模板选「博友动态」；或者随便哪个页面，内容里写 `[wbf_boyou]`

插件自己带前台模板，外壳仍然走主题的 header / footer —— 导航、页脚、配色都还是主题的，换主题不用改代码。样式优先吃主题变量，主题没定义变量时按正文文字色派生兜底，深色浅色都能跟。

**要求**：WordPress 5.5+、PHP 7.4+、服务器能访问你的 FreshRSS。

## 第一次用：先同步，再看账

同步把订阅里的文章拉到 `wp-content/uploads/wp-boyou-feed/boyou.json`，前台页面读这个本地文件，**不会每次访问都去打 FreshRSS**。定时任务按设置的小时数跑（默认 6 小时）。

对账页第一次打开会慢一点：同步数据只覆盖最近一个月，一个月内没动静的站，打开页面时才会现查它的最新文章。每站一次请求，查一次管 24 小时，所以第一次会看到一批「查询中」，第二次打开就都是结果了。

## 互访对账是怎么算的

| 档位 | 含义 |
|---|---|
| 常来 | 3 个月内来留过言 |
| 偶尔 | 3 个月到 1 年没来 |
| 冷淡 | 1 到 2 年没来 |
| 失联 | 2 年以上没来 |
| 单向 | 订阅了，但从没来你博客留过言 |

两条口径，都是踩过坑才定下来的：

- **域名定站，邮箱认人。** 同一个人换了域名来留言，光看域名会判成「失联 6 年」——实际上人一直在。现在按邮箱认出来，表里会标一行「以 xxx 留言」，告诉你他是用哪个站来的。
- **填 GitHub / 微博 / 知乎这类主页的不算。** 那些站没有 feed，标出来只会提醒你去订一个订不了的东西，所以直接排除。

排序是「失联 → 冷淡 → 偶尔 → 常来 → 单向」。单向那一大坨放最后是有意的：订阅里从没来过的往往最多，排前面会把真正该看的失联站挤到几屏以外。

## 久未更新 和 站点异常

两列是两个维度，别混着看：

- **更新**回答「他自己的站还活着吗」
- **来访**回答「他还来不来我这儿」

删订阅这件事，两样得一起看。半年以上没发文的标黄，一年以上标红，按停更时长排，删除按钮就在同一行。

**FreshRSS 说他没更新，不算结论。** 实测它的接口根本不吐抓取错误状态 —— 它抓不动和站真死了，从接口上看是一样的。所以打开对账页时会二次复核：feed 和站点各访问一次，两个都打不开才算数。

| 复核结果 | 说明 | 标记 |
|---|---|---|
| feed 通、站点通 | 站活得好好的，只是没更新，或者 FreshRSS 自己没抓到 | 不标 |
| feed 挂、站点活 | 可能人家换了 feed 地址 | 黄「feed 异常」，别急着删 |
| 两个都打不开 | 域名解析失败 / 证书错误 / 403 / 连接超时，原因写在行里 | 红「站点无法访问」 |

复核结果缓存三天，不会反复请求同一个站。复核只访问订阅快照里记着的地址，内网地址一律拒绝 —— 防的是有人借这个接口探内网。

实测 58 个久未更新的站里，复核出 22 个真死站、9 个 feed 异常，还有 2 个站被复核救了回来：feed 明明通着，是 FreshRSS 自己没抓到。

## 常见问题

**问：页头「订阅 N 个」和 FreshRSS 里的数字对不上？**

数的是订阅清单的长度，不是「这次有文章回来的站数」。差得多就点一次「立即同步」，再刷页面。

**问：前台还是旧内容？**

同步是定时的，先在后台点「立即同步」。同步完了前台还不动，就是页面缓存 —— 清一次缓存插件的缓存（WP Rocket、LiteSpeed、W3TC 之类）。

**问：可以用别人给的 JSON 吗？**

设置里「自定义 JSON 地址」填了就走那个地址，格式和插件自己生成的 `boyou.json` 一样。留空就用本地文件。

**问：为什么「单向」这么多？**

订阅里本来大半是从没来留过言的站 —— 你订他，不代表他来看你。这一档是给你看真实比例用的，不是让你去删。

**问：一个 WordPress 能管几个站的订阅？**

一套设置对应一个 FreshRSS 账号。多个站点就各填各的，互不影响。

**问：停用插件会留下什么？**

定时同步任务在停用时就清掉了，不会再空跑。文章数据文件留在 `uploads/wp-boyou-feed/` 里，重装后接着用。

## 一点实现说明

- **option 名是 `riven_rss_*`**，插件叫博友动态却用 `riven` 前缀，是因为它最早长在主题里，改名等于老站的 FreshRSS 配置、同步时间、每页条数全部失效。这是数据契约，不改。
- 前台模板由插件接管（`template_include`），主题里那份 `template-rss.php` 可以删掉，不影响任何判断。
- 自更新走作者更新源，后台会像普通插件一样提示新版本。
